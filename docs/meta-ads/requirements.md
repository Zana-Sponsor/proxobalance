# Meta/TikTok v8 requirement traceability

The combined PR subsequently received [TikTok v15](../tiktok-dm/requirements.md). Its final payment appendices explicitly apply to both Meta and TikTok and override earlier conflicting inline/unselected payment wording below: compact selected-method card, confirmed wallet default, Change-only editing through the shared modal sheet, temporary selection committed by Confirm, and selected-only visible checks. The receipt-preservation rule remains unchanged; no new logo slot or receipt layout is authorized.

The governing source is the owner's `Meta_TikTok_Ads_Implementation_Prompt_EN_UPDATED_v8_ReceiptLogoOnly(1).txt`. The document revision is **v8**; the application order contract is **schema version 3**. Later authoritative appendices override earlier conflicting text. This is a coverage and verification map, not a claim that external configuration or live acceptance has passed.

The receipt appendix is the latest change: reuse the approved advertisement receipt exactly; only an **existing** platform-logo slot may vary. The inspected receipt has Proxo branding but no separate platform-logo slot. Preserving it is intentional; inventing a slot or replacing the Proxo mark would violate v8. See [handover and unresolved items](README.md).

The owner's authoritative v8 wording is:

> The existing Proxo advertisement receipt design is approved.
>
> DO NOT redesign it for Meta.
>
> The ONLY intended platform-specific visual difference in the receipt is the platform logo shown in the existing platform-logo slot:
>
> - Meta order -> Meta logo
> - TikTok order -> TikTok logo

This overrides conflicting earlier receipt instructions. Facebook-only and Instagram-only orders still use Meta identity; neither Facebook nor Instagram may replace the receipt platform logo. The current absence of that slot is an explicit unresolved design anchor, not permission to add one.

## Evidence conventions

- **Source** identifies the implementation or existing component to inspect. Its presence alone does not prove end-to-end behavior.
- **Local** means isolated Node, Flutter, database, or screenshot checks using synthetic data. It does not establish Meta account eligibility, target n8n import, payment-gateway behavior, or device performance.
- **External** requires the owner's configured services/authorized assets and controlled staging verification. No paid delivery is authorized by this work.
- A requirement remains open when its required external evidence, screenshot comparison, or existing design anchor is absent. The README records concrete test results; this matrix intentionally does not turn a source path into a blanket “complete” status.

Paths below are relative to the repository root. `lib/` abbreviates `proxo_app/lib/`; `migration` means `proxo_app/supabase/migrations/20261022235825_meta_ads_private_v3.sql`.
