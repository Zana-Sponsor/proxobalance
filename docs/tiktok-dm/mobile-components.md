# TikTok Direct Message mobile components

`TikTokDmAccountPicker` extends the existing Create Ad form through `AdFormSection`, `AdUi`, `AdChoice`, `ProxoText`, and the bundled TikTok brand asset. It does not create a messaging inbox or call TikTok from Flutter.

The account and add-account capsules share a measured height at the current text scale. Connected capsules place the real avatar at the RTL leading edge, the verified username next, and the disconnect action at the trailing edge. The add capsule uses the TikTok logo and a dashed border. Disconnect requires an explicit confirmation dialog.

The compact video carousel appears only after selecting a ready account. A paginated selector sheet supports browsing more videos. Metadata is cached by authenticated owner and connected account, but a fresh server read is required before selection. Explicit server `dm_ready: false` remains authoritative even when legacy capability flags are true. Unknown visibility or advertising eligibility is excluded. Confirmed offline status hides selectable cards immediately, including an open browser sheet. Account changes, owner changes, refreshes, and permission errors invalidate the active selection; late responses cannot replace the current account's list. Returning to Direct restores only the last valid account after revalidation, never a previously selected video.

`TikTokDmConnectSheet` requests a server-owned authorization session, renders only a returned HTTPS TikTok authorization URL, and polls the Proxo backend with bounded backoff while active. Repeated checks coalesce. Closing the sheet or backgrounding stops polling. A status-only response preserves the same session's requested username and QR URL. A mismatch remains an error; the verified account never replaces the requested username silently.

The authorization provider currently fails closed with `TIKTOK_AUTH_CORRELATION_UNAVAILABLE` until a supported, verifiable session-to-identity correlation is configured. UI fixtures with synthetic URLs demonstrate rendering/state behavior only; they do not establish live authorization support.

The QR bitmap is generated locally using the already resolved `qr` 3.0.2 package. Its four-module quiet zone is preserved. [`tiktok_qr_tutorial.dart`](../../proxo_app/lib/widgets/tiktok_qr_tutorial.dart) is original bundled vector animation code: it draws a generic phone and scan line without screenshots, external assets, provider UI copies, or authorization data. Reduced-motion settings render a still frame.

The 13 focused mobile tests cover public-only video filtering, account-switch races, last-account restoration, cache invalidation on offline errors/events, equal capsule geometry at 280 logical pixels/200% text, disconnect confirmation, rejection of unrelated QR origins, QR expiry, and polling/lifecycle coalescing. They also render the bundled Kurdish fonts. Live account authorization and real TikTok Direct Message delivery require the separate staging acceptance gates.

Rendered fixture evidence: [account controls at 393px](../../proxo_app/docs/tiktok_dm_evidence/accounts_393.png), [account controls at 280px/200% text](../../proxo_app/docs/tiktok_dm_evidence/accounts_280.png), and [QR sheet at 393px](../../proxo_app/docs/tiktok_dm_evidence/qr_fixture_393.png). These use synthetic identities, no avatar/video URLs, and a synthetic official-domain URL. They demonstrate layout and QR encoding, not a connected TikTok account or working live authorization.
