## Causes and recovery

- **Create Page startup:** the configured `https://www.proxobalance.app/api/page-providers` returns HTTP 404, verified by read-only checks on October 20 and again October 22 at 18:25:57 UTC. This fails catalog initialization before the form or submission can run. Retry makes another real request but cannot deploy the missing route. See [page evidence](pages.md).
- **Page form lock:** retained `_submitted` data made fields read-only after uncertain failure. Editing now resumes while the request UUID is preserved for idempotent recovery. Local cleanup no longer masks a confirmed result.
- **Advertisement lock:** persisted pending requests wrapped the whole form in `IgnorePointer`; the resume navigation path lacked its own guaranteed cleanup, and broad network classification retained locks after definitive database rejection. Form state is now independent of pending-request reconciliation; only verified rollback codes clear the pending identity. Connection errors and unknown transaction outcomes keep it.
- **Late cleanup race:** timing out a platform storage cleanup must not allow it to erase a later request. Page/ad storage operations are serialized per owner; caller deadlines do not abandon the durable operation queue. Top-up keys keep their existing serialized ordering.
- **Notifications:** overlapping queued cards, long deadlines and multiple animation/timer paths were replaced by a single content-sized surface with a first-frame deadline and screen-lifecycle cleanup.
- **Immediate rejection after a dialog closes:** a visibility dependency update could erase a newly received error. Notices now check the live route/tab state and clear hidden/stale messages without discarding fresh feedback from the returning screen.
- **Near-midnight scheduling:** Baghdad calendar fields were compared as UTC instants against device-local picker values. This could reject a valid future time on another timezone's device. Creation, saved drafts and validation now preserve and compare the same Baghdad calendar fields, including device daylight-saving gaps.
- **Android Back:** the native profile run reached 32 screen markers, then Android finished the activity when Back was pressed with the drawer open. A platform-channel regression reproduced the cause: Flutter 3.47's root drawer adds local route history without updating Android's ahead-of-time Back registration. The shared drawer callback now dispatches the live navigation state. Existing route vetoes remain intact. Native verification also checks registration and activity survival explicitly.
- **Runtime test hang:** the driver awaited a stopped VM; the SDK timeout argument only warned, and the Python runner collected diagnostics only after a normal return. The host now has a real 10-minute Future deadline, a 20-minute process-group limit and a 15-second Back acknowledgement limit. Failure paths retain device diagnostics and partial captures/measurements instead of waiting for the CI job's 40-minute cancellation.
- **Checkout logo and narrow rows:** a legacy square JPG's padding reduced its visible wordmark to roughly 23×6dp in a 28dp header. All three uses now share the verified official artwork. At 320dp/200% text, unconstrained summary labels starved the reference/countdown; responsive stacked rows now preserve their full usable width, copy and scrolling.
- Visual verification also caught and repaired AppBar title scale/wrapping inheritance, an unnecessary spinner behind FastPay checkout, a narrow Profile OTP action wrapping into a lone letter, and a repeated free-receipt payment section that caused an extra PDF page.
